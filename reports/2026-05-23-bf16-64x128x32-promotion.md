# 2026-05-23 BF16 prefill 64x128x32 promotion

## Goal

Test whether BF16 prefill benefits from the same `KGroup=2` mainloop idea that
was already promoted for f16 prefill N>K shapes.

## Candidate

`zcutlass_sm120_tensorop_bf16_64x128x32_aligned_prefill`

- `BlockM=64`, `BlockN=128`, `KGroup=2`, `tile_k=32`.
- Restricted to `ShapeFamily::Prefill`.
- Aligned/no-beta/no-bias fast path only.
- Replaces the previous BF16 prefill default
  `zcutlass_sm120_tensorop_bf16_64x128x16_aligned`.

## Benchmark Result

Prefill-only regression gate:

| Shape | Baseline ms | Candidate ms | Speedup |
| --- | ---: | ---: | ---: |
| `bf16 128x4096x4096` | 0.2838 | 0.2560 | 1.1086x |
| `bf16 128x16384x4096` | 0.8826 | 0.8291 | 1.0645x |
| `bf16 128x4096x16384` | 1.6936 | 1.5664 | 1.0812x |

Geomean speedup: `1.0846x`.

After promotion, a rerun with the default dispatch selected
`zcutlass_sm120_tensorop_bf16_64x128x32_aligned_prefill` for all three BF16
prefill shapes and passed the prefill regression gate at `1.0871x` geomean
speedup. The first promoted suite run had a transient slow `128x16384x4096`
measurement where cuBLAS also slowed substantially; the rerun matched the
experimental result.

## Nsight Summary

Compared with the previous BF16 `64x128x16` prefill profile for
`128x4096x4096`:

| Metric | KGroup=1 | KGroup=2 |
| --- | ---: | ---: |
| SM throughput | 13.82% | 14.43% |
| Tensor active | 9.16% | 9.53% |
| DRAM throughput | 8.41% | 9.05% |
| Registers/thread | 72 | 71 |
| Shared memory/block | 39.94 KiB | 46.08 KiB |
| Long scoreboard stall | 8.70 inst | 9.51 inst |
| Barrier stall | 0.61 inst | 0.25 inst |

The long-scoreboard signal worsened, but benchmark latency, tensor/SM
throughput, register count, and barrier stalls all moved in the right direction.
This is good enough to promote for BF16 prefill while leaving long-scoreboard
reduction as the next kernel-design target.

## Decision

Promote BF16 `64x128x32` as the default aligned prefill path. Keep the BF16
`64x128x16_aligned` kernel for large/throughput and fallback-adjacent aligned
coverage.

## Framework Trace Check

After promotion, the zcutlass extension was rebuilt inside
`/home/zyz/vllm/.venv`. A BF16 vLLM LinearMethod probe for
`128x4096x4096` recorded `hit_rate=1.0` and selected
`zcutlass_sm120_tensorop_bf16_64x128x32_aligned_prefill` with tile
`64x128x32`.

The framework probe still trails vLLM's native GEMM path, so this promotion is a
kernel-library step, not an end-to-end serving value claim.
